# GLOSSARY-001 总名词解释

这份文档回答一个问题：**每个词在本项目里只有一个意思，它是哪个意思。**

状态说明：全表 48 条词条中，46 条为 `active`，2 条为 `proposed`（「用户故事」「阶段门验收」，2026-11-01 由模型补登记，待开发者审定）。文档、代码标识符、界面文案只能使用 `active` 词条；`proposed` 词条仅作登记。

用词提醒：本表「文档状态」与「事项状态」是两条不同词条。引用其它文档 front-matter 的字段时写 `status`，指代文档正文首段的内容时写「状态」，二者取值集合不同，不得互借（详见 `INDEX-001` §5 与 GOV-000 §4.5 约束 7）。

## 1. 使用规则

| 编号 | 规则 |
|---|---|
| G-1 | 一个概念只有一个正式词条；其他写法登记为「禁用写法」，不得出现在文档、代码与界面中 |
| G-2 | 定义中不得引用未登记词条 |
| G-3 | 代码标识符（表名、类名、接口路径、字段名）必须与英文名一致 |
| G-4 | 界面文案必须使用中文词条，不得使用禁用写法 |
| G-5 | 新增词条由模型提出 `proposed`，开发者确认后转 `active`，模型不得自行置为 `active` |
| G-6 | 词条修订属全局口径变更，须走 RFC 并在末尾记录变更历史 |
| G-7 | 作废词条不得删除，状态改为 `deprecated` 并注明替代词条 |
| G-8 | 「示例」栏的第一性是让读者从用法里理解定义，例如该词条造一个句子；不得写该词条在本项目中的实际使用情况 |
| G-9 | 「变更记录」按时间顺序向下追加，只增不改、不插入、不重排；开发者手工追加的行保持其原位置 |

### 2.6 编号前缀对照
