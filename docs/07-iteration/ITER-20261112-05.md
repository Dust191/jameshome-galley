# ITER-20261112-05

这份记录回答三个问题：签名地址在真实桶上成不成立、ACR 怎么转存、0.2.0 怎么发。

## 一、资源与凭据

| 项 | 值 |
|---|---|
| OSS 桶 | `jameshome-galley`（私有） |
| ACR 实例 | `crpi-8wtwv1zju2g9kpgg.cn-hangzhou.personal.cr.aliyuncs.com`（个人版，实例域名与通用的 `registry.cn-hangzhou.aliyuncs.com` 不同） |
| ACR 命名空间 | `jameshome-galley` |
| 已登录位置 | 云主机 `~/.docker/config.json` 仅有该实例 |

## 二、签名地址实测

用真实桶跑了一次「上传 → 签名 → 直接 GET → 删除」，临时测试类用完即删、未入库：

```
SIGNED_HOST=jameshome-galley.oss-cn-hangzhou.aliyuncs.com
STATUS=200
```

结论：MinIO SDK 的 V4 预签名在 OSS 标准 endpoint 上可用，**不再需要 S3 兼容域名**；后端读写仍走内网 endpoint，签名走公网 endpoint，两条路互不干扰。

## 三、ACR 转存

| 镜像 | 操作 | 结果 |
|---|---|---|
| `caddy:2-alpine` | 云上经 7892 隧道拉取 → tag → push | 成功，可再次从 ACR 拉取 |
| `cloudflare/cloudflared:2026.10.7` | 同上 | 成功 |

顺带把 dockerd 的 `NO_PROXY` 加上 `.aliyuncs.com`：推 ACR 属于国内直连，绕隧道推 50 MB 没有意义。

## 四、版本与发布

- `pom.xml` 0.1.0 → **0.2.0**；`CHANGELOG` 补 0.2.0 段（审计、限流、签名 URL、编排、入口、提交信息 CI）
- 打 `v0.2.0` tag 触发 `release.yml`：矩阵构建 `galley-api` / `galley-web` 并推 GHCR
- 镜像 tag 由 semver 归一为 `0.2.0`，与编排默认值一致
