## 三、变更过程

### 3.1 做法

1. 开局 `git status --short` 与 `git diff`：两轮迭代记录已由开发者手改为 `approved` 并填好审定三行（审定时间 2026-11-14、结论通过），本轮原样纳入提交，不改写。
2. 重裁依据三条事实：① 阿里云消息中心已订阅安全消息与异常通知（站内信 + 短信 + 邮件），平台侧事件无需自建；② Cloudflare 终结 TLS，服务器侧无自有证书，原「证书剩余 <14 天」不成立；③ 业务层发信已有公共区域发信地址 `ecs-alert@dust181.aliyun.com`，走 `SingleSendMail`，不必引入第三方。
3. 划界线定为「云监控能直接观测到的就不自建」：CPU / 内存 / 磁盘 / 网络、ECS 故障、账号安全归平台层；探针、隧道、5xx、P95、备份、对账归业务层。
4. 补齐一处旧有分歧：`DEV-009` 的七条里有证书、`RUN-001` 的七条里有隧道断连，两处清单本就不同。本轮统一为两张清单，隧道以「入口失效」进入业务层。

### 3.2 遇到的问题与处理

| 编号 | 问题 | 处理 |
|---|---|---|
| P-1 | 只改 `DEV-009` 会让 `RUN-001` 继续指向旧口径，两份文档各说一套 | 同批改 `RUN-001` §10，只保留首响动作，判据统一指向 `RUN-003` |
| P-2 | 磁盘告警既云监控可见、又能用 `df` 自建，两种归属都说得通 | 归平台层，避免与云监控重复；`RUN-003` §3 注明「插件缺失时该条不成立」 |
| P-3 | 业务层的 P95 需要指标，而当前 actuator 只暴露 `health,info` | 不在文档里假定已具备；`RUN-003` §6 列为依赖，写明「开启 metrics 或改用访问日志统计」 |
