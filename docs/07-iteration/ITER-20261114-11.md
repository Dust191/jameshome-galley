## 三、变更过程

### 3.1 做法

1. 五项计数合并成一次查询：物料表只扫一遍，结存表只连一次。
2. 发 0.2.1 时先升版本号、更新 CHANGELOG 与模板，再打 tag 触发 `release.yml`。
3. 0.2.1 实测仍差 54ms，用 `EXPLAIN` 复查，发现两件事：合并查询漏了 `quantity > 0`，且 `NOT EXISTS` 仍对 5 万个物料逐行执行。
4. 0.2.2 改为「先聚出近 90 天有出库的物料，再反连接」，同时补回口径条件。

### 3.2 遇到的问题与处理

| 编号 | 问题 | 处理 |
|---|---|---|
| P-1 | 0.2.1 的 CI 在 guards 失败：契约 `info.version` 仍是 0.2.0，与 pom 的 0.2.1 不一致 | 补一次 `fix(release)` 提交把契约同步到 0.2.1；此后 0.2.2 一并改 |
| P-2 | 镜像拉取报 `proxyconnect tcp: dial tcp 127.0.0.1:7892: connect: connection refused` | 实测两条链路：经隧道 000（5 秒超时），直连 401（0.56 秒）——直连可用，问题在 daemon 全局代理 |
| P-3 | `NO_PROXY` 只加 `ghcr.io` 后仍失败：manifest 通了，层下载卡住 | 镜像层在 `objects.githubusercontent.com` 等域名上，一并加入 `NO_PROXY`；为此重启了两次 docker |
| P-4 | 两次重启 docker 导致 9 个容器全量重启，prod 中断约 3 分钟，Quick Tunnel 换址 | 事后确认 prod 五服务 healthy、api 200；新入口 `https://passage-bet-rfc-cam.trycloudflare.com`，符合 `DVT-13` 的换址预期 |
| P-5 | 拉取镜像两次被 `timeout 600` 掐断，第二次只差最后一层，镜像未落地 | 改为后台任务并放宽到 30 分钟，重拉 |
| P-6 | 0.2.1 的合并查询漏了 `quantity > 0`，零结存与负结存被算作呆滞 | 发现于 `EXPLAIN` 复查时的口径比对；0.2.2 补回，并在注释里写明这条不能省 |
