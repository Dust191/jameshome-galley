## 三、变更过程

### 3.1 上一版为什么不合格

上一版把 GOV-000 压成 145 行，并在 §1 写了两条理由：搬进来会与实现分叉、新贡献者读不完。第一条是事实，第二条不是理由——**规范的价值在于可核对，不在于短**。压成摘要的直接后果是：

- GOV-000 的许多条款在仓内没有落点，读者只能回外部文件；
- 摘要不写"这一条在本仓由什么执行"，规则与实现脱节；
- 被省略的条款恰好包括未实现的部分，于是"规范写了但没做"看不出来。

本轮改为四分册：总纲、作业、阶段、团体。拆分依据是读者与变更频率，四份合计 1594 行，与 GOV-000 的 1696 行同量级；§7 给出逐章对照，确保没有一章被丢掉。

### 3.2 怎么保证"根据实际情况"

写之前逐项核对代码与配置，不照抄 GOV-000 的版本号与断言：

| 核对项 | 方法 | 结果 |
|---|---|---|
| 技术版本 | 读 `backend/pom.xml`、`frontend/package.json`、`maven-wrapper.properties` | Boot 4.1.2、MyBatis-Plus 3.5.18.1、Maven 3.9.16、JaCoCo 0.8.16、ArchUnit 1.5.1；与 GOV-000 多处不同 |
| 接口规模 | 数 `contracts/openapi.yaml` | 32 条路径 / 41 个操作（`DEV-005` 记的 40 个业务端点，差额是 `/healthz`） |
| 数据模型 | 读 `V1__init_schema.sql` | 八张业务表（含 `unit`、`invite_code`）+ 两张会话表 |
| 门禁范围 | 读 `ci.yml` 与四个脚本 | `guards` 只跑契约、环境变量、署名、文档；提交信息未接入 |
| 审计 | 全局搜 `audit` 与写入路径 | 只有建表语句，无 Java/XML 引用，`created_by` / `updated_by` 未填 |
| 注册限流 | 读 `AuthService` | 只有登录失败锁定，注册无频率限制 |
| 分页与软删 | 读 `MaterialService`、`BalanceMapper.xml` | 服务层钳制 100 + 显式 `LIMIT/OFFSET`；软删显式写 `deleted_at`，未用框架插件 |

### 3.3 发现的缺口

三条新偏离里，`DVT-08` 与 `DVT-09` 是首次被记录：

- **写操作未落审计**：`SCOPE-001` 把它列为 In，`PRD-001` 口令重置验收 3 依赖它，红线 7 也写着"写操作必须写审计"，但 `audit_log` 从未被写入。G3 的 12 条 UAT 没有一条覆盖审计，因此门通过了而事实不成立。
- **注册端点未限流**：`SCOPE-001` In 项（决策 D-20）要求注册限流，实现只有邀请码校验。
- **提交信息未接入 CI**：`DEV-002` 原文写"两者都在 CI 里跑"，实际只有署名在跑；机器人提交的 `deps-dev` scope 与超长 subject 会误伤，这是它一直没被接入的原因。

`DVT-08` 的影响最大：它让"写操作可追溯"这句话在 0.1.0 上不成立。已同步登记 `TD-15`，并把收回时点定在 S5 开启前——G5 安全组第 6 项（依赖与自查）与数据组都绕不开它。

另有四项不计偏离，按性质写进 `DEV-009` §5.9：盘点按分类批量录入只做了单条、物料恢复入口未做、导入模板未提供（这三项属范围缺口）、图片按 `ADR-0005` 用 `publicUrl` 而非私有读（属设计决策）。

写作过程中被门禁拦下三次，记在这里避免下轮重犯：

| 编号 | 问题 | 处理 |
|---|---|---|
| P-1 | `spec-work` 两处表格只隔一个空行，被 `check-docs` 判为表格断开 | 中间插入引导句 |
| P-2 | `spec-stages` 命中禁用写法"规划、存量、余量、用户名、接口文档"；`spec` 命中"品类、里程碑、检查点、周期" | 逐处换词：排期、遗留、剩余空间、账号名、接口契约、物料种类、0.5.0、落点、全阶段 |
| P-3 | 三处统计口径写错：四份规范写成"约 1500 行"、文档数写成"66 → 70 份" | 以 `wc -l` 与 `check-docs` 输出为准，改为 1594 行、61 → 65 份（模板 5 → 7 份） |
