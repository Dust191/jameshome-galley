## 二、环境重建

虚拟机重启后容器全部停止，按 `DEV-001` 的步骤恢复：

1. `docker start galley-db galley-minio`（PG 18.3 与 MinIO 均正常，健康检查 200）
2. `ssh -N -L 15432:127.0.0.1:5432 -L 19000:127.0.0.1:9000 -L 19001:127.0.0.1:9001 dust@192.168.91.128`
3. 后端：`./mvnw spring-boot:run`，`--server.port=18080` 覆盖环境里注入的 `SERVER_PORT`
4. 前端：`GALLEY_API_TARGET=http://127.0.0.1:18080 pnpm dev --host 127.0.0.1 --port 5173`

MinIO 桶策略与对象均保留，重启后图片 URL 仍可直接访问（实测 200 / `image/png`）。
管理员密码按 `BootstrapAdmin` 的开发策略**随每次启动重新生成**，从启动日志读取。

## 三、自检发现的问题与修法

| 序 | 问题 | 影响 | 修法 |
|---|---|---|---|
| 1 | `QtyInput` 把 `0` 一律判为非法 | 安全库存填 0（表示不设预警线）会红字报"数量不能为 0"，而表单初始值正是 0 | `clampQty` 增加 `allowZero` 参数，安全库存字段传入 |
| 2 | `MaterialFormPage` 在 hook 之前条件 `return` | 角色变化时 hook 数量改变，React 会直接抛错；当前靠 `RequireAuth` 挡在 loading 期间才未触发 | 改为先算 `forbidden` 标志，全部 hook 执行完再拦；相关查询加 `enabled` |
| 3 | 后端用户可见提示仍用"口令""红冲" | 登录失败、改密失败、冲正失败等提示直接显示给用户，属返工要求 1 的遗漏 | 统一为"密码""冲正"，共 10 处；中文提示全量复核 69 条 |
| 4 | 导出 CSV 输出内部枚举 `active` / `REVERSAL` | Excel 里看到的是数据库取值，不是给人看的文字 | 导出层加 `materialStatusLabel` / `movementTypeLabel`，状态与类型一律中文 |
| 5 | 登录按钮无提交反馈 | 弱网下用户会重复点击 | 增加 `submitting` 状态与"登录中…" |

另删除未接线的 `qtyRules`（导出但无人调用）；表单层校验已在各表单的 `rules` 内实现，避免留下"看起来有兜底、实际没接线"的死代码。
