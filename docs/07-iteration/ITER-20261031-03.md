### 3.2 遇到的问题与处理

| 编号 | 问题 | 处理 |
|---|---|---|
| P-1 | Spotless 调用 google-java-format 1.24.0 时抛 `NoSuchMethodError: Log$DeferredDiagnosticHandler.getDiagnostics()`，该版本依赖的 javac 内部 API 在 JDK 25 已变更 | 升到 1.29.0（同属格式化器，不动三大基线）；升级后 `spotless:check` 正常 |
| P-2 | ArchUnit 四条规则全部失败，原因是「rule failed to check any classes」——0.23 起空集默认判为失败，而骨架期模块包内只有 `package-info` | 每条规则加 `allowEmptyShould(true)`，并在测试注释中写明「S3 建立实现后收回该开关」 |
| P-3 | JaCoCo 0.8.12 无法分析 class 文件 major version 69，`test` 阶段生成报告时失败 | 升到 0.8.16。**这是对 GOV-000 §1.5 的偏离**，登记在第五节 |
| P-4 | `check-signoff.sh` 用 `git log --format` 单行解析，提交正文含多行时被拆成多条记录，导致误报 | 改为 `git rev-list` 逐条 `git show -s` 取值；同时把符号 `✗` 换成 ASCII `[FAIL]`，避免终端编码干扰 |
| P-5 | `check-contract.sh` 取 pom 第一个 `<version>`，误取到 parent 的 4.1.2 | 改为按 `<artifactId>galley</artifactId>` 定位项目自身版本 |
| P-6 | 本机无 Docker，`/actuator/health` 因数据库不可达无法返回 | `/healthz` 已实测通过；actuator 健康检查改在虚拟机内验证，登记为遗留 |

### 10.2 补测中发现的问题

| 编号 | 问题 | 处理 |
|---|---|---|
| P-7 | **PostgreSQL 18 官方镜像的挂载点已变更**：必须挂到 `/var/lib/postgresql`，沿用 17 及以前的 `/var/lib/postgresql/data` 会让容器直接退出并提示 pg_upgrade | 修正 `compose.dev.yml`；该条属镜像行为变更，任何"照抄旧编排"的做法都会踩到 |
| P-8 | **pnpm 10+ 默认拦截依赖的安装脚本**，`esbuild` 的 postinstall 被拦后 `install` 以退出码 1 失败；`package.json` 的 `pnpm` 字段在 pnpm 12 已不再被读取，改 `pnpm-workspace.yaml` 与 `.npmrc` 两种写法仍未放行 | 锁定 pnpm 9.15.9（`packageManager` 字段），与 CI 声明一致；README 前置条件补明 |
| P-9 | 宿主环境存在 `GALLEY_SERVER_PORT=12888`，覆盖 `application.yml` 的默认端口，首次启动报「Port 12888 already in use」 | 属环境变量污染，非项目缺陷；验证时以 `env -u` 清除。反向说明：默认值被环境静默覆盖时，日志应打印实际端口（S3 补） |
| P-10 | 本机 HTTP 代理会拦截 `localhost` 请求，`curl` 表现为「upstream connect failed」，易被误判为服务未启动 | 验证命令统一加 `--noproxy '*'`；写入 `DEV-001` 的常见问题（S2） |
