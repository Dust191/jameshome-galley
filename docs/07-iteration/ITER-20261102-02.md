## 三、变更过程

### 3.1 执行步骤

1. 先确认依赖可用：Maven 经本机 7890 代理解析，`spring-session-jdbc` 与 security starter 已在 BOM 内。
2. 按 ArchUnit 的既有规则分包：`domain` 不依赖框架、`api` 不碰 `infrastructure`、Controller 不暴露 `DO`。
3. 写通用层：错误码枚举直接对齐 `DES-002` §3，避免"文档一套、代码一套"。
4. 写认证：登录走 `AuthenticationManager`，成功后显式 `saveContext` 到 JDBC 会话；改密后重建会话权限，否则 `MUST_CHANGE_PASSWORD` 标记会一直挂着。
5. 写「必须改密」过滤器：放行改密/登出/查自己，其余一律 403 —— 放在过滤器而不是每个接口，漏一个也不会被绕过。
6. 会话表由 Flyway 建（V2），`initialize-schema=never` 防止应用启动时重复建表。

### 3.2 遇到的问题与处理

| 编号 | 问题 | 处理 |
|---|---|---|
| P-1 | `com.fasterxml.jackson.databind` 不存在：Spring Boot 4 默认 Jackson 3 | 改用 `tools.jackson.databind.ObjectMapper` |
| P-2 | Spotless 对 9 个新文件报格式违规 | 按 `DEV-001` 的约定跑 `spotless:apply`，不手工调格式 |
| P-3 | 邀请码的"不存在/已用/已禁用"在 `DES-002` 表里是两个错误码，而 D-18 要求不区分原因 | 统一返回 `INVITE_CODE_INVALID`，并在代码注释写明依据；`DES-002` 表的 `INVITE_CODE_DISABLED` 暂不启用，待回写文档 |
| P-4 | 审计列 `created_by/updated_by` 需要当前用户，但会话里只有用户名 | 本轮先留空；T4 接入 `audit_log` 时统一处理，避免两处各写一套取用户逻辑 |
