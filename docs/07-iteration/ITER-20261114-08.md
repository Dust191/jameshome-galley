## 三、变更过程

### 3.1 做法

1. 造数前采基线：磁盘 19%、容器合计约 690 MB、prod 五服务连跑 40 小时。
2. 分三步：生成 TSV（38 秒、423 MB）→ 导入（先小表与物料，再单独导流水）→ 聚合并 ANALYZE。
3. 压测按「先 1 并发探测，按结果决定是否加压」推进，没有一上来就上 8 并发。

### 3.2 遇到的问题与处理

| 编号 | 问题 | 处理 |
|---|---|---|
| P-1 | 导入 200 万流水的 ssh 会话被 10 分钟上限杀掉，`COPY` 输出没回显 | 立即查状态：表里 200 万行齐、prod 健康 200、磁盘 9.1 GB。判定事务已提交，只是输出丢失；后续长任务应放 `nohup` 或分段跑 |
| P-2 | 1 并发压测 P50 就到 2927ms，15 秒只完成 9 个请求 | 停止加压。逐路径测：`overview` 3.1 秒、`materials` 0.13 秒、`balances` 0.37 秒——问题被隔离到一条接口 |
| P-3 | 怀疑 `ANALYZE` 缺失，做了一遍仍 3 秒 | 排除统计信息因素，转向执行计划 |

### 3.3 验证手段与结果

| 项 | 结果 |
|---|---|
| 导入结果 | 8 分类 / 6 单位 / 50000 物料 / 2000000 流水 / 50000 结存（负结存 16，属允许范围） |
| 结存聚合 | 7 秒 |
| ANALYZE | 3 秒 |
| 逐路径耗时（各 2 次） | `overview` 3.10 / 3.00 秒；`materials` 0.13 / 0.12 秒；`balances` 0.37 / 0.20 秒 |
| 压测（1 并发 / 15 秒） | 9 请求、0 错误、P50 2927ms、P95 3379ms、CPU 峰值 66.9%、内存 75.1%、磁盘 23.1% |
| 执行计划 | M-7 呆滞物料查询 2877ms：`Parallel Hash Right Anti Join` + 对 90 天内流水的 `Bitmap Heap Scan`，过滤掉 35 万行 |
| 生产影响 | prod 五服务全程 healthy，未重启；内存可用从 593 MB 降到 456 MB |
