## 三、变更过程

### 3.1 执行步骤

1. 依 D-17 ~ D-20 更新 ITER-20261031-01 与 GOV-000（v1.5 → v1.6），先将口令方案、邀请码语义、环境状态、限流要求落定。
2. 先写 `00-glossary.md`：按 GOV-000 §0.5 的必登记词条为骨架，扩到 34 条，覆盖定位、领域、账号权限、流程四类。
3. 再写 `PRD-001`：以 glossary 的词条为唯一用词来源，按 F1 / F2 / F3 拆故事，每条给 2–4 条可断言验收。
4. 写 `scope.md`：把 PRD 的不做清单展开为带理由的三列，并把「已注册账号处理」单列为 S3 议题。
5. 写 `nfr.md`：六维取自 GOV-000 §2.4，补入实测环境与偏差处置。
6. 写三份 ADR：技术栈、目录结构、代码规范工具。
7. 写 `00-index.md` 登记全部文档，并暴露 GOV-000 的位置问题。
8. 自查：逐份核对 front-matter 字段完整、`related` 目标均存在、用词未超出 glossary。

### 3.2 遇到的问题与处理

| 编号 | 问题 | 处理 |
|---|---|---|
| P-1 | glossary 全部为 `proposed`，而规则要求文档正文只能使用 `active` 词条，两者在确认前互相卡住 | 全部 S0 文档置为 `status: draft`，视作"引用待确认词条"；开发者确认后一次性把词条转 `active`，文档同步转 `review`。此路径写入 glossary §3 |
| P-2 | 指标由 10 项减为 9 项，而 GOV-000 §2.4 的范围表写「约 10 项统计指标」 | 9 项仍在"约"的容差内，不构成冲突；在 `DES-004` 中以显式清单为准并注明总数 |
| P-3 | GOV-000 位于 `docs/` 之外且 1600 余行，违反其自身 §4.5 约束 1（`docs/` 外 Markdown ≤100 行） | 未擅自迁移（迁移会改变开发者已引用的路径），登记为 `00-index.md` §4 的已知位置问题，待 S2 定处置 |
| P-4 | ADR-0001 正文状态为 `accepted`，front-matter 却是 `draft`，读起来矛盾 | 在正文首段写明：`draft` 指记录表述未经审定，不指决策未定 |
| P-5 | 导出上限 50000 行与「禁止无 limit 的集合查询」存在张力 | 导出不属集合查询而是数据导出，但实现方式（流式 / 分批游标）会影响内存与超时，登记为遗留 L-02，在 S3 定 |

### 3.3 验证手段与结果

- 验证方式：文档自查（front-matter 字段、`related` 目标存在性、用词反查）。
- 结果：9 份文档 front-matter 齐全；`related` 指向的 `GLOSSARY-001`、`PRD-001`、`SCOPE-001`、`NFR-001`、`ADR-0001`~`0003`、`INDEX-001` 均已存在。
- 未验证：CI 的 front-matter 与用词校验尚未建立（属 S2），当前为人工自查；S2 建立后需回溯跑一次。
