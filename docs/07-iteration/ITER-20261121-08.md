## 三、变更过程

### 3.1 做法

**S-2 复核**：用收窄后的 AK 直接跑备份脚本。第一次失败在回查环节——`ossutil stat` 会额外请求对象 ACL（`?acl`），需要 `oss:GetObjectAcl`。

这里没有选择「再加一个权限」，而是改脚本：`ossutil ls` 在现有策略下已经能返回大小与 ETag，回查照样能验到 MD5。少一条权限，比多一条更接近最小权限的本意。

**O-2 处置**：按开发者决定移出 G5。检查单的结果取值增加「跳过」，与「暂缓」区分——暂缓按未通过计，跳过不计入门但必须在结论里单列，不能悄悄消失。

**关门三件套**：`RUN-004` 填结论与签字 → `DEV-009` 标题与阶段状态转达成，判据原文用删除线标注 O-2 已移出 → 新建 `GOV-009` 记录结论、证据、偏离与遗留。

### 3.2 遇到的问题与处理

| 编号 | 问题 | 处理 |
|---|---|---|
| P-1 | `ossutil stat` 报 `You have no right to access this object because of bucket acl` | 改脚本用 `ls` 回查；策略不扩容，反而更窄 |
| P-2 | 改完 `ls` 解析后报「远端大小 CST 与本地不一致」 | 列格式是「日期 时间 时区 CST 大小 存储类型 ETAG 对象名」，大小在第 5 列不是第 4 列；修正后通过 |
| P-3 | 批量改 `DEV-009` 时 `iter` 值断言失败（该文件当时指向 `ITER-20261121-04`） | 按实际值重跑，未产生半写状态 |
| P-4 | 提交信息写成 `docs(governance): …`，`governance` 不在白名单 | 提交后跑校验脚本当场发现，amend 为 `docs(docs)`；按 `GOV-007` 登记 `MDV-09`，同类第五次 |
