## 三、变更过程

### 3.1 为什么不直接复制 GOV-000

GOV-000 共 1696 行，其中 S5 / S6 两阶段尚未进入、附录含大量示例与推演。整体搬进 `docs/` 有三个后果：
与实现分叉后没有人维护、新贡献者读不完、以及「规范写了但没做」的条款反而模糊了执行标准。

INDEX 2026-10-31 的裁定已经给出正解：**另写一份依当前实现收敛的本地化版本**。本轮照此执行。

### 3.2 收敛原则

| 原则 | 做法 |
|---|---|
| 只写已经发生的 | 阶段表只列到 G4；S5/S6 标注「未开启」，不写细则 |
| 只写可执行的 | 每条规则都给出执行处（脚本、文件、PR 流程），没有执行处的愿望不入文 |
| 与细节文档分工 | 流程与门进 DEV-006；代码细节指向 `DEV-002`；测试细节指向 `DEV-003`；发布细节指向 `GOV-002` |
| 与新贡献者对得上 | 凡是外部可见的动作（提 PR、提交格式、评审）在 `CONTRIBUTING` 有逐条操作，DEV-006 只做索引 |

### 3.3 偏离为什么单独立账

此前偏离散在三处：`ITER-20261031-03` 的 DVT-01 ~ 03、`GOV-003` §3、`GOV-006` §3。
散着记的后果是「查一条偏离要翻三份文档，而且没人知道还有没有别的」。
本轮把台账独立成 `DEV-007`，并补齐三条一直存在但没入账的：分支保护的管理员通道、机器人不参与签署、OWASP 未执行。

### 3.4 验证手段与结果

| 项 | 结果 |
|---|---|
| `node scripts/check-docs.mjs` | 通过：61 份文档，doc_id 唯一、索引与 related 一致、禁用写法零命中 |
| 前缀一致性 | `DEV-006/007` 与 `DVT-NN` 不冲突，前缀表已刷新 |
| 内容核对 | 阶段状态、质量门数值、检查名均取自当前实现（`backend/pom.xml`、`scripts/`、Actions 实测） |
