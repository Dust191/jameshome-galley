## 三、变更过程

### 3.1 做法

开发者开启虚拟机后在其上实测。虚拟机原本只有 Docker，JDK、Node、pnpm 都没有，且无免密 sudo，因此把三者装到用户目录：

- JDK 25.0.5（Adoptium，清华镜像解包到 `~/opt/jdk-25`）
- Node 22.22.2（同镜像解包到 `~/opt/node`）
- pnpm 9.15.9（用 Node 自带 corepack 激活到 `~/opt/bin`）

把工作区同步到 `~/galley-c1` 后，按 README 的顺序执行并分段计时。

### 3.2 遇到的问题与处理

| 编号 | 问题 | 处理 |
|---|---|---|
| P-1 | 虚拟机没有 `make`，README 的前置里也没写 | 记为 README 缺口，前置补上「`make` 要单独装」 |
| P-2 | `make setup` 最后一步 `compose pull` 失败：`docker.io` 直连 `EOF` | 记为 README 缺口，补「国内网络需配镜像源或代理；开发模式只需 `postgres:18.3`」 |
| P-3 | 首次启动等了 450 秒仍未通过健康检查 | 不当作失败处理：依赖仍在下载（`.m2` 已 139 MB）；随后一次 18 秒起来，说明下载在第一次的时间窗内完成，合计约 7.8 分钟 |
| P-4 | `make` 缺失导致无法原样执行 README | 按 `Makefile` 里 setup 展开的命令逐步执行，等价计时；不修改仓库 |

### 3.3 验证手段与结果

| 项 | 结果 |
