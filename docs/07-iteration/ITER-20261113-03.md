## 三、变更过程

### 3.1 做法

1. 开局 `git status --short` 与 `git diff`：工作区干净，只有未跟踪的 `docs/idea.md`，无他人改动。
2. README 的数据逐项实测后写入：契约 32 条路径 / 41 个操作（`grep` 契约文件）、109 个 `@Test`（`grep` 测试源码）、8 张领域表 + 2 张会话表（`DES-001` 与迁移脚本）、3 条 E2E（`frontend/e2e/flows.spec.ts`）。
3. 易漂移的数量不写死：前端页面改为按功能点描述，不报路由条数；性能与覆盖率只写门槛值，实测值注明出自 0.1.0。
4. 旧表述按「只增不删可改」处理：`GOV-006` 的备案项加删除线，原文一字不删，补记写明移出上线验收的依据与轮次。

### 3.2 遇到的问题与处理

| 编号 | 问题 | 处理 |
|---|---|---|
| P-1 | 「只增不改」原按「不修改既定正文」执行，遇到确需更正的错误就没有合法出口 | 按开发者本轮裁定改为「只增不删可改」：加删除线后修正，原文保留，另起补记说明现口径 |
| P-2 | `GOV-006` 是 `approved` 阶段门记录，一旦改动，其 `updated` 与索引登记行会不一致 | 同批改索引；`ITER` 计数一并更新，避免只改一侧 |
| P-3 | 原 README 写「11 个路由」与「0.1.0」，前者无法核对、后者已过时 | 页面改为按功能点列举，版本改为 0.2.0；凡引用实测数字均标注实测日期或版本 |
| P-4 | `DEV-006` §3.1 的部署形态位于「产品与边界」章，改写有越权风险 | 只改部署形态这一句，不动定位与三条硬边界；删除线标出被替换的措辞，补注 `DVT-10` / `DVT-11` |
