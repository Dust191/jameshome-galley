## 三、变更过程

### 3.1 做法

- **为什么成败都计数**：限流防的是"高频尝试"这件事本身；只数失败会放行"慢慢试"的枚举行为。
- **为什么只取 XFF 首跳**：链条上只有第一跳由我们自己的 Caddy 追加、不可伪造；后面的跳都可由客户端自带伪造。
- **为什么连带 `Retry-After`**：`DES-002` §3 本来就规定 429 必须带它，登录失败锁定同样返回 429——一起补齐，避免留一个新的"契约写了没实现"。

### 3.2 模拟评审（对抗式自查）

| 编号 | 发现 | 处置 |
|---|---|---|
| P-1 | 首个集成测试用例的账号名 `rate-over` / `rate-ok` 带 `-`，不满足 `^[a-z0-9_]{3,32}$`，得到 400 而非预期状态——**这个 400 差点被误判成"限流没生效"** | 用户名改为 `rateover` / `rateok`；断言消息临时带响应体定位后移除 |
| P-2 | 测试客户端全部来自 127.0.0.1，与其他用例共享同一 IP，限流计数会跨用例累积 | `resetDatabase` 同时清零限流器，不新增 Spring 上下文 |
| P-3 | `guards` 的 job `name` 是必需检查上下文 | 未触碰工作流（本 PR 不改 CI） |
| P-4 | 新配置若走 `GALLEY_*` 环境变量会触发 `.env.example` 一致性联动 | 键值直接写在 `application.yml`，不新增环境变量 |

### 3.3 验证手段与结果

| 项 | 结果 |
|---|---|
| `RegisterRateLimiterTest`（单元，无 Docker） | 5 / 5 通过 |
| `RegisterRateLimitEndpointTest`（集成，Testcontainers 经 2375 隧道连虚拟机 Docker） | 2 / 2 通过：第 11 次 429 + `Retry-After` ∈ [1,600]；未超限注册 201 |
| 全量 `mvn verify` | 117 个用例全绿（原 110 + 新增 7），覆盖率门槛全过 |
| 契约 / 环境变量 / 署名 / 提交信息 / 文档校验 | 全过 |
