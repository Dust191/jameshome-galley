# ITER-20261112-09

这份记录回答三个问题：哪些文档已经和实现对不上、改了哪些、哪些刻意没改。

## 一、核查范围与方法

逐份读 `docs/03-dev/`、`docs/04-ops/` 的现行文档，按三条判据找漂移：

1. 命令能否照抄执行（服务名、路径、参数、端口）；
2. 状态描述是否与 `git log`、CI 结果、线上实况一致；
3. 是否把“当时的决定”写成了“现在的事实”。

历史记录（`docs/07-iteration/`、`GOV-003`、`GOV-006`、`uat-v0.1.md`）按只增不改处理，发现不符只在本文记一笔，不回头改原文。

## 二、改了什么

### `RUN-001` 整篇重写（改得最多）

| 原文问题 | 实际 | 处理 |
|---|---|---|
| 用容器名 `galley` 写命令 | 容器名是 `galley-api-1`，服务名是 `api` | 统一改用服务名 + `docker compose` 调用，开头定义 `C=` 变量 |
| `curl 127.0.0.1:8080/actuator/...` | `api` 只 `expose 8080`，未发布到宿主机，宿主上 curl 必失败 | 改为 `$C exec -T api curl ...`，并把这条列为“最容易误判为应用挂了” |
| 证书过期 → `restart caddy` | TLS 由 Cloudflare 边缘持有，本机 `caddy` 只有内网 `:80`，无证书可续 | 删除该行，改为指向 Cloudflare 侧 |
| 无入口失效章节 | Quick Tunnel 重启即换址（`DVT-13`），这是当前最高频故障 | 新增 §5，含取址命令与 502 / 1033 的判断 |
| 无内存章节 | 2 GB 内存跑五服务，构建与批量导入时最易 OOM | 新增 §3，含 `dmesg` 判据与收敛顺序 |
| 只有 4 类故障 | §7.6 要求八类 | 新增 §11 八类对照表，逐条指向章节 |
