## 四、关键发现

1. **架构规则一直是摆设**：ArchUnit 1.3.0 无法解析 Java 25 的 class 文件，`importPackages` 得到 0 个类；
   骨架期用 `allowEmptyShould(true)` 掩盖了这一点。升级 1.5.1 并收回开关后，四条规则才真正开始检查。
2. **测试容器的两个坑**：Spring 上下文会跨测试类缓存，若每个类各起一个容器，第二个类会连到已停的端口；
   改为整个 JVM 共用一个容器。另，流水表有"不可改删"触发器，测试清库必须用 `TRUNCATE` 而不是 `DELETE`。
3. **测试客户端的精度陷阱**：`ObjectMapper.readTree` 默认把小数解析成 double，`10.000` 变成 `10.0`，
   断言分不清精度；解析时开启 `USE_BIG_DECIMAL_FOR_FLOATS` 才与接口返回一致。
4. **对账必须用 left join**：从未入库的物料没有结存行，内连接会让它们直接消失，差异被掩盖。
5. **性能实测**：在独立库 `galley_perf` 生成 5 万物料 + 200 万流水；测量经 SSH 隧道，比同机部署更悲观，
   结果仍远低于门槛。
