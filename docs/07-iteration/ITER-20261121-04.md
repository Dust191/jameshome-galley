## 三、变更过程

### 3.1 做法

检查单原本只允许两个结果。O-2 既不是「已通过」，也不是普通的「未通过」——它的实现已完成，卡在一个外部条件上。为免把这种状态塞进「未通过」里含糊过去，新增第三种取值：

- **暂缓**只由开发者下指令使用，必须写明原因与解除条件；
- 门结论里暂缓按**未通过**计，一票否决项暂缓时门同样不开。

O-2 的证据列写清三层：规则已落成并空跑通过；DirectMail 因「发信地址必须收验证码到自身」而不可用；发信通道已有 SMTP 备选。解除条件写「域名到位并完成 DNS 验证」。

### 3.2 遇到的问题与处理

| 编号 | 问题 | 处理 |
|---|---|---|
| P-1 | 「暂缓」若不计入门结论，等于把一票否决项悄悄放行 | 明确按未通过计，并在结论行写「一票否决 O-2 暂缓中」 |
| P-2 | 汇总表原为三列，加状态后列数不齐 | 改为「通过 / 未通过 / 暂缓 / 一票否决」四列，补合计行 |
| P-3 | `DEV-009` 与检查单两处写 O-2 状态，容易只改一处 | 两处同批改，并在 `DEV-009` 变更记录留痕 |
