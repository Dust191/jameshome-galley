## 三、变更过程

### 3.1 执行步骤

1. 盘点现状：13 份文档的 front-matter `status` 取值分为 `approved` / `review` / `draft` 三类，其中 `review` 不在约定的取值集合内。
2. 在 GOV-000 §4.5 落约束 7，把两套取值写死：`status` 为 `draft / in_review / accepted / rejected / approved`，「状态」为 `draft / pending / accepted / rejected / resolved`。
3. 在 `00-index.md` 新增 §5，用一张对照表说明两者描述的对象不同，并给出一条判据：`status: draft` 只表示文档表述未经审定，不表示决策未定。
4. 逐份修正 front-matter：4 份 ITER 的 `review` → `in_review`；ADR-0004 依开发者标注转 `approved`。
5. 反向清理用词：把索引表头与首段中把 front-matter 字段称作「状态」的地方改为 `status`。
6. glossary 补两条状态类词条，并把全表 46 条统一为 `active`。

## 六、与上轮的差异摘要

上轮解决"同一个前缀两个意思"（`DEV` 撞名），本轮解决"同一个词两个层面"（`status` 与「状态」）。
两轮是同一类问题的两次复发：**术语没有唯一所指，就会在文档里长出歧义**。处理方式也一样——先在 glossary 登记，再写死取值，最后反向清扫存量文档。
