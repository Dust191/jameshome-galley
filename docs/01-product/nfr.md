# NFR-001 非功能需求基线

这份文档回答一个问题：**"够快、够稳、够安全"分别等于多少。**
全部指标给数值与测量口径，不出现"较快""尽量""良好"一类表述。任何一项在 G3 未达标即不得放行。

## 1. 六维基线

| 维度 | 指标 | 口径 |
|---|---|---|
| 性能 | 库存总览 P95 ≤500ms | 5 万物料、200 万流水、并发 20，从请求发起到响应体接收完成 |
| 性能 | 物料列表 P95 ≤300ms | 同上数据集，默认分页 20，含按名称模糊与按分类筛选 |
| 性能 | 首屏可交互 ≤2s | 4G 网络（下行 9Mbps、RTT 100ms），移动端视口 360×640 |
| 容量 | 5 万物料、200 万流水、50 账号、日活 50 | 超过任一项即触发架构评审，不得静默扩容了事 |
| 可用性 | 月度 ≥99% | 计划内维护每月不超过 2 小时，不计入不可用时长 |
| 安全 | OWASP Top 10 自查通过；依赖无 High / Critical | 每次发版前执行；自查表留档 |
| 兼容 | Chrome / Edge / Safari 最近 2 个大版本 | 移动端浏览器只读视图可用；不要求 IE 与已 EOL 版本 |
| 无障碍 | 表单可键盘操作；正文对比度 ≥4.5:1 | WCAG 2.1 AA 关键项；以 axe 自动检查 + 人工键盘走查为准 |

## 2. 测量环境与偏差声明

性能指标在开发机实测，不等同生产环境。按决策 D-08 与 D-15：

| 项 | 约定 |
|---|---|
| 测量位置 | Ubuntu 24.04 虚拟机 `192.168.91.128`，容器内运行被测服务与 PostgreSQL 18 |
| 数据来源 | 固定种子数据（5 万物料、200 万流水），由脚本可重复生成，不使用生产数据 |
| 必须记录 | 每次实测须在 `docs/03-dev/uat-v0.1.md` 记录：CPU/内存规格、并发数、数据集版本、P50/P95/P99 |
| 偏差处置 | 若实测值与目标差距超 20%，须在 G3 记录偏差原因与生产预估；生产环境首次上线后 2 周内复测，结果写入 `docs/04-ops/monitoring.md` |
| 不接受的替代 | 不得以"数据量减半后达标"作为通过依据；数据集必须足量 |

## 3. 各维度的落地要求

| 维度 | 落地要求 |
|---|---|
| 性能 | 统计查询必须有索引支撑；禁止无 `limit` 的集合查询；禁止循环内查库 |
| 容量 | 列表接口单页上限 100；导出单次上限 50000 行，超出返回 422 |
| 可用性 | 单机部署，接受计划内维护；健康检查分 liveness（不查库）与 readiness（查库） |
| 安全 | 口令单向哈希存储；会话存库；上传做类型白名单 + 大小限制 + 服务端二次校验；生产禁止返回堆栈 |
| 兼容 | 只读视图优先适配移动端；表格容器内横向滚动，关键字段不折叠 |
| 无障碍 | 表单元素有可读标签；错误提示与字段关联；键盘可达全部操作 |

## 4. 未达标的处置

| 情形 | 处置 |
|---|---|
| 性能未达标 | 先定位慢查询与索引，禁止通过降低数据量或放宽口径"达标" |
| 安全项未通过 | 阻塞发布，按缺陷处理，不得以"下版修复"放行 |
| 兼容项未通过 | 阻塞发布；至少保证主流两版浏览器 + 移动端只读可用 |
| 可用性未达标 | 记入 `RUN-001` 并分析根因；连续两月未达标触发架构评审 |

## 5. 变更规则

容量或部署形态变化时，本文件须同步更新并走一次评审；指标口径变更属全局变更，须走 RFC（与红线 9 一致）。
