# PRD-003 未来展望与推进方向

这份文档回答一个问题：**1.0.0 正式上线之后，项目往哪里走、按什么顺序、什么不做。**

本文是方向性文件，不构成承诺；每项进入执行前仍按 `DEV-008` 立轮次、按 `SCOPE-001` 的边界校验。三条硬边界（非商业 / 不改写现场作业 / 不做组织集成）继续有效。

## 1. S6：协作与运营期（当前阶段，2026-11-21 起）

单人开发阶段随 1.0.0 结束，进入团队开发模式——规范已就位（`DEV-010` 生效），重点是**照着执行并留下痕迹**：

| 方向 | 内容 | 依据 |
|---|---|---|
| 协作落地 | 冷静期、自审十项、季度离线演练（首次演练 S6 内执行） | `DEV-010` §3、§8.2 |
| 度量 | 建立度量文件（`D6-3`），每月五项：覆盖率、issue 首响、发布频率、变更前置时间、回滚次数 | `DEV-009` §7.9 |
| 发布说明 | GitHub Release 正文补齐（`D6-5`），1.0.0 起每个 tag 都有正文 | `DEV-009` §7.9 |
| 文档门禁 | 链接校验与到期标记（`TD-17`） | `DEV-004` |
| Roadmap 维护 | 本文档每季度复核一次（`D6-4`） | 本表 |

## 2. 正式入口与告警（随域名推进）

上线后第一优先级，因为它们依赖同一个外部条件——**购买个人域名**（做邮件推送与 Named Tunnel 均不需要 ICP 备案）：

1. 域名 DNS 验证 → DirectMail 发信地址验证 → `alert-agent.py` 切回 DirectMail 或走 SMTP。
2. 逐条触发六条业务规则与平台层四条（`RUN-003` §7），`O-2` 正式闭环。
3. 域名 + Named Tunnel + 备案后切正式入口，收回 `DVT-13`（`T5-06`）。

## 3. 安全缺口（`GOV-008` 排期）

| 编号 | 缺口 | 处置 |
|---|---|---|
| G-1 | 备份为明文 dump | OSS 服务端加密或本地加密后上传 |
| G-2 | 会话 Cookie 未显式声明 SameSite / Secure | 随下一版在 `application.yml` 配置 |
| G-3 | 未做威胁建模 | S6 内补一次，写入 ADR |
| G-4 | 业务告警暂缓 | 随本文 §2 解除 |

## 4. 技术债（按 `DEV-004` 台账，择机偿还）

`TD-02`（toolchains）、`TD-06`（组件测试框架）、`TD-10`（5 条 moderate）、`TD-11`（E2E 固定凭据）、`TD-12`（antd 按需引入）、`TD-13`（库存口径合并）、`TD-17`（文档门禁增强）。均不阻塞运行，按触达时顺手偿还。

## 5. 功能候选（全部待评审，未立项）

以下仅是方向池，任何一项立项都需先过 `SCOPE-001` 边界与 `PRD-001` 场景核对：

- **导入增强**：Excel 导入、字段映射模板、导入预览与回滚。
- **多仓库视图**：单团体内的多库房/多冰柜维度，结存与流水按仓库拆分。
- **报表**：月度盘点报表、损耗趋势，导出 PDF。
- **移动端体验**：PWA 化、离线暂存补录。
- **通知扩展**：预警推送到值班人手机（依赖 §2 的通道）。

## 6. 什么不做

- 不做组织集成（多团体、多租户）——见 `SCOPE-001` 不做清单。
- 不改写现场作业流程——工具跟着现有习惯走。
- 不做商业化功能——授权、计费、营销一律不在范围。
- 不引入消息队列、微服务拆分——单机五服务在当前容量下足够，容量触发评审再议（NFR 容量线）。

## 7. 扩编信号

满足 `DEV-010` §4.3 的任意两条即启动扩编评估；在此之前维持单人 + 模型协作，规范不豁免。
