# SCOPE-001 范围冻结表

这份文档回答一个问题：**这一版做什么、不做什么、什么事情只记录不实现。**
本表在 G0 通过后冻结。新增需求只能进入「参考方向」或下个 minor，不得插入当前 MVP；例外仅限数据错误类缺陷。

## 1. 冻结表

| 类别 | 内容 | 理由 |
|---|---|---|
| In | 物料建档与编辑（名称、分类、规格、单位、安全库存、保质期、图片、备注） | 一切记录的前提，缺此无对象可登记 |
| In | 出入库登记（`IN` / `OUT`）与按分类盘点录入（`ADJUST`） | 构成数量变化的三类事实来源 |
| In | 红冲（`REVERSAL`） | 流水只增不改，修正只能靠红冲，否则账实不可追溯 |
| In | 库存总览、物料列表、物料详情（结存 + 流水时间线） | 远程查看的核心价值所在 |
| In | 9 项统计指标（含低库存、零库存、呆滞物料数与预警清单） | 让"哪些快没了"可被一眼看出；指标清单见 `DES-004` |
| In | 分类字典维护（新增、重命名、排序、占用校验） | 分类是筛选与汇总的维度 |
| In | 三角色权限（`admin` / `editor` / `viewer`）与只读优先的界面 | 让远程查看者能安全地只读 |
| In | CSV 导入（物料）与 CSV 导出（**物料与流水两个独立入口**） | 首次建账必须能批量；线下核对必须能导出（决策 D-08） |
| In | 图片上传（jpg/png/webp、≤5MB、服务端二次校验、私有读） | 现场识别物料常靠图，非可选装饰 |
| In | 注册（凭邀请码）、登录、口令重置、邀请码管理 | 账号自建是三条硬边界第 3 条的直接推论；邀请码限定入口，避免公开注册（决策 D-08、D-13） |
| In | 注册端点限流 | 注册页对未登录用户开放，无限制即可被爆破邀请码（决策 D-20） |
| In | 审计日志（所有写操作记录执行者、时间、变更前后快照） | 红冲与停用若无审计，等于没有约束 |
| In | 每日结存对账任务（02:00 按流水重算并比对） | 库存系统可信度的底线 |
| Out | 支付、结算、采购付款 | 违反硬边界 1，红线 1 |
| Out | 采购下单、供应商管理 | 属现场作业系统职责，违反硬边界 2 |
| Out | 菜品与菜单管理 | 与"库存远程查看"无因果关系 |
| Out | 库存硬件控制（电子秤、温湿度、门禁）与称重对接 | 违反硬边界 2，且属参考方向 |
| Out | 组织架构、OA / HR 集成、统一认证、手机号与身份证等敏感信息 | 违反硬边界 3，且触碰红线 5 |
| Out | 消息推送（短信、邮件、IM） | 首版无通知渠道，预警靠页面查看 |
| Out | 多厨房界面、多库位切换 | 单点厨房是本版唯一定位，多点是参考方向 |
| Out | 移动端原生应用 | 手机浏览器已满足远程查看，原生应用成本与定位不符 |
| Out | PDF 报表 | CSV 已覆盖线下核对需求 |
| Out | **盘点单、盘点差异分析报表、复盘** | 本版盘点只做"按分类录入实盘数 → 生成 `ADJUST`"，不做盘点单与差异分析（决策 D-07） |
| Out | 单位换算 | 不同单位数量不得相加（红线 9），换算属参考方向 |
| Out | 暗色模式、主题定制 | 体验优化，非首版必需 |
| 参考方向 | 批次与效期（先进先出、临期预警） | 加在流水上的一个维度，需先评估对 U2 的影响 |
| 参考方向 | 多库位 / 多厨房 | 改变"一个物料一个结存"的假设，属结构性扩展 |
| 参考方向 | 补货提醒（基于安全库存与消耗速度，不含付款） | 依赖消耗速度口径，需先稳定指标 |
| 参考方向 | 盘点作业（盘点单、差异分析、复盘） | 本版已明确排除，后续单独立项 |
| 参考方向 | 出入库审批（大额出库双人确认） | 引入流程状态机，与单人场景不匹配 |
| 参考方向 | 移动端扫码 | 依赖外部输入设备与编码体系 |
| 参考方向 | 报表订阅（定期导出与推送） | 依赖推送渠道 |
| 参考方向 | 称重设备对接 | 违反硬边界 2 的现状，需重新审定边界 |
| 待 S3 讨论 | 已注册账号的禁用、删除、角色回收方式 | 本版只定义未使用邀请码的禁用；账号侧处置留待账号模块设计时定（决策 D-18） |

> In：MVP 必做；Out：明确不做；参考方向：上线（G5）以先不做

## 2. 冻结规则

| 编号 | 规则 |
|---|---|
| 1 | 本表通过 G0 后，In 列不再增加；新增需求进「参考方向」或下个 minor |
| 2 | 例外仅限数据错误类缺陷（如结存算错），且须在迭代记录中单独说明 |
| 3 | Out 列的条目不得以"顺手做一下"的形式出现，包括隐藏入口、未公开接口、预埋字段 |
| 4 | 参考方向的任何一条，在上线（G5）前不得开发，也不得为其实现在模型中预埋字段或表 |
| 5 | 判断某功能是否属范围外时，以本表 + PRD-001 §5 为准；两处冲突时以本表为准并回改 PRD |

## 3. 与通用基础的关系

本表 In 列的每一项都必须落在四条通用基础上（GOV-000 §1.4）：对象通用（物料建模、字典驱动）、结构通用（主数据 + 流水 + 结存）、口径通用（统计只依赖流水与字典）、边界通用（只暴露 REST + OpenAPI）。凡需破坏其中任一条才能实现的需求，一律退回参考方向。
