# DES-004 统计指标口径

这份文档回答一个问题：**每个数字是怎么算出来的，两次数出来为什么必须一样。**

口径一经确定，任何人按本文件手算都应与系统输出一致；不一致即为缺陷，而不是"口径不同"。本文属口径定义，变更须走 RFC。

## 1. 目标与非目标

| 项 | 内容 |
|---|---|
| 本文件解决 | 9 项指标的公式、数据源、时间窗口、边界与排序 |
| 本文件不解决 | 这些数字在界面上怎么画（`DES-003`）、接口形状（`DES-002`） |

## 2. 通用口径

以下五条适用于全部指标，单项不再重复。

| 编号 | 口径 | 说明 |
|---|---|---|
| C-1 | **时区** | 数据存 `timestamptz`（UTC），一切自然日按 `Asia/Shanghai` 切分。窗口边界写法：`[T 00:00:00.000, T 23:59:59.999]` |
| C-2 | **窗口终点** | 一律取"当日 23:59:59.999"，不取"当前时刻"。这样同一天内多次请求，只要没有新写入，结果完全相同（PRD US-S3 验收 1） |
| C-3 | **有效期内的物料** | 除特别说明，均只统计 `material.status = 'active'`；停用、归档物料不计入任何数 |
| C-4 | **排序确定性** | 所有列表必须有唯一确定的次序：先按指标值降序，值相同再按 `material.name` 升序，仍相同按 `material.id` 升序。禁止依赖数据库默认顺序 |
| C-5 | **单位不相加** | 任何响应中不得出现跨单位求和的数量字段（PRD US-S3 验收 2）。库存总量只能表达为"物料种类数"或"按单位分组的数量" |

## 3. 指标清单

九项，与 PRD US-S3 验收 3 一一对应。

| 序 | 指标 | 类型 | 数据源 |
|---|---|---|---|
| M-1 | 在管物料种类数 | 标量 | `material` |
| M-2 | 低库存物料数 | 标量 | `material` + `stock_balance` |
| M-3 | 零库存物料数 | 标量 | `stock_balance` |
| M-4 | 分类分布 | 分组 | `material` + `material_category` |
| M-5 | 出入库笔数趋势 | 时序（30 点） | `stock_movement` |
| M-6 | 出库频次 Top10 | 列表（≤10） | `stock_movement` |
| M-7 | 呆滞物料数 | 标量 | `stock_movement` + `stock_balance` |
| M-8 | 数据完整率 | 比率 | `material` |
| M-9 | 预警清单 | 列表 | M-2 / M-3 / M-7 合并 |

### M-1 在管物料种类数

```
count(material) where status = 'active'
```

不按单位、不按分类拆分；这是唯一允许跨单位出现的"总量"，因为它数的是**种类**不是数量。

### M-2 低库存物料数

```
count(material m join stock_balance b on b.material_id = m.id)
where m.status = 'active'
  and b.quantity < m.safety_stock
```

- 比较是**严格小于**：`quantity = safety_stock` 不算低库存（正好踩线属正常）。
- `safety_stock = 0` 且 `quantity < 0` 时计入——负结存比安全库存还低，本就更严重。
- 无结存记录的物料（刚建档未入过库）视为 `quantity = 0`，参与比较。

### M-3 零库存物料数

```
count(*) where quantity = 0 and material.status = 'active'
```

- 精确等于 0，不含负库存。负库存单列在 M-9 的严重度最高档。
- 数量为 `numeric(14,3)`，比较不用浮点近似。

### M-4 分类分布

```
按 category 分组：
  种类数 = count(material)
  占比   = 种类数 / M-1
```

- 占比保留 4 位小数，四舍五入；各行占比之和可能不等于 1（舍入误差），**不做强制配平**。
- 分类为 `inactive` 但有物料的，仍单列一行，名称后缀"（已停用）"，不并入其它分类。
- 排序：种类数降序 → 分类名升序。

### M-5 出入库笔数趋势

```
近 30 个自然日（含今日），逐日：
  IN 笔数  = count(type = 'IN')
  OUT 笔数 = count(type = 'OUT')
```

- 窗口：`[T-29 00:00, T 23:59:59.999]`，T 为 `Asia/Shanghai` 的今天。
- **必须补齐 30 个点**：无流水的日子返回 0，不允许跳日，否则前端折线会错位。
- 计数口径见 §4：以有效流水计，被红冲的原始流水与红冲流水本身都不计入。
- 同日多笔合并为一点；顺序按日期升序。

### M-6 出库频次 Top10

```
近 30 天按 material 分组：
  频次 = count(type = 'OUT')
取前 10，频次降序
```

- 并列时按物料名升序，保证同一数据集输出稳定（C-4）。
- 不足 10 条返回实际条数，不补空行。
- 频次为 0 的物料不出现，不占位。

### M-7 呆滞物料数

```
count(material m)
where m.status = 'active'
  and b.quantity > 0
  and 近 90 天内无有效 OUT 流水
```

- "近 90 天"窗口同 C-2：`[T-89 00:00, T 23:59:59.999]`。
- 从未有过任何流水、但结存 > 0 的物料（如仅通过导入建档），计入呆滞。
- 红冲掉的 OUT 不算"有出库"，见 §4。

### M-8 数据完整率

```
比率 = 完整物料数 / M-1
完整 = spec 非空 且 safety_stock > 0
```

口径说明（Q-2 采纳 A）：

- 原口径要求"分类、规格、单位、安全库存四项齐全"，但分类与单位在建表层面为 `NOT NULL`，永远成立，判定实际只取决于后两项。
- `safety_stock` 虽为必填，但默认值为 0；**0 视为未设置**——安全库存为 0 意味着这条物料不做低库存预警，等同于没配。因此判据取 `> 0` 而非"非空"。
- 结果保留 2 位小数，如 `0.75` 表示 75% 的物料资料齐全。

### M-9 预警清单

由 M-2、M-3、M-7 的成员合并去重，按严重度排序：

| 严重度 | 条件 | 判定 |
|---|---|---|
| 3（最高） | `quantity < 0` | 负库存，账实已不符 |
| 2 | `quantity = 0` | 断货 |
| 1 | `quantity < safety_stock` 且 `> 0` | 低于安全线 |
| 0 | 结存 > 0 且 90 天无出库 | 呆滞 |

- 同一物料命中多个条件时取最高严重度，只出现一次。
- 排序：严重度降序 → 结存升序 → 物料名升序。

## 4. 红冲在统计中的处理

这是本文件最容易出错的一条，单列说明。

| 口径 | 规则 |
|---|---|
| 计入 | 未被红冲的 `IN` / `OUT` / `ADJUST` 流水 |
| 不计入 | `type = 'REVERSAL'` 的流水本身（它是抵消手段，不是业务动作） |
| 不计入 | `reversed = true` 的原始流水（已被抵消） |

也就是说，统计看的是**净业务动作**：一笔出库被红冲后，M-5 的 OUT 笔数减一、M-6 的频次减一、M-7 可能因此变呆滞。

> 注意与 `DES-001` §4.1 的区别：**结存**按全部流水求和（含被红冲的原流水与红冲流水），**统计笔数**按有效流水计。两处口径不同且都有依据，不得互相"统一"。
