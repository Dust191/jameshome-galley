# ADR-0004 JDK 采用两级锁定：大版本对齐、补丁由本机 Toolchains 锁定

这份文档回答一个问题：**"JDK 版本锁死"到底锁到哪一位。**
本 ADR 取代 ADR-0001 §2.1 与 §3 中"CI 与生产镜像同版本（25.0.4.1）"的表述，其余决策不变。

- **状态**：accepted（依据开发者 2026-11-01 裁定）
- **取代**：ADR-0001 的版本粒度部分

## 1. 背景

原规范要求 JDK 版本由 Maven Toolchains 与 CI 镜像"双重锁定为 25.0.4.1"。S1 首次真实运行 CI 时观测到：`actions/setup-java@v4` 配 `java-version: "25"`，解析出的是 **Temurin 25.0.5+8**，与本机 25.0.4.1 的补丁号不一致。

把 `ci.yml` 写死成 `25.0.4.1` 看似能对齐，但它把流水线绑死在一个具体构建上：上游一旦撤回或未发布该构建，CI 直接红，而这类失败与代码质量无关。

## 2. 选项与代价

| 选项 | 代价 |
|---|---|
| **两级锁定：大版本 25 对齐；补丁由本机 Toolchains 锁定（采用）** | CI 补丁号可能领先本机；须在每轮 ITER 记录 CI 实际版本，版本差异需人工留意 |
| CI 写死 `25.0.4.1` | 依赖 Temurin 是否长期保留该构建；构建被撤回即全流水线失败；每升一次补丁都要改工作流 |
| 完全放开，只要求"能编译" | 本机与 CI 可能跨大版本，出现"本地能跑、CI 不能"的经典故障，且无法复现 |

## 3. 决策

| 层 | 锁定方式 | 当前取值 |
|---|---|---|
| 大版本 | CI 镜像与本机环境均须为 JDK 25 | 25 |
| 补丁号（本机） | Maven Toolchains（`toolchains.xml` + `maven-toolchains-plugin`）精确指定 | 25.0.4.1 |
| 补丁号（CI） | 取同大版本最新可用补丁 | Temurin 25.0.5+8 |
| 生产镜像 | 与 CI 同大版本的 JRE | S5 定稿 |
| 记录义务 | 每轮 ITER 的"轮次信息"须写明 CI 实际 JDK 版本 | — |

约束原文同步改为 GOV-000 v1.8 §3.5 约束 4。

## 4. 后果

**好的**：CI 不会因某个补丁构建被撤回而失败；本机仍能精确复现编译环境；升级补丁只需改 `toolchains.xml` 一处。

**坏的**：CI 与本机存在补丁级差异，理论上可能出现"CI 过、本机不过"的边界情况；缓解手段是把差异写进每轮记录，出现异常时优先怀疑版本差。

**需要后续偿还的**：`toolchains.xml` 尚未建立（S3 前补），在此之前本机实际使用的是 `JAVA_HOME` 指向的 25.0.4.1，与"由 Toolchains 锁定"尚有一步差距，已登记为遗留。
