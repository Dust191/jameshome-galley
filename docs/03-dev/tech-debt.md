# DEV-004 技术债台账

这份文档回答一个问题：**哪些地方明知不够好、打算什么时候还。**

入账标准：**知道不对、暂时不修、且不修有代价**。三样缺一不入账——"以后再说"不是债，"没办法"也不是债。

## 3. 记账规则

| 规则 | 说明 |
|---|---|
| 每轮末检查 | ITER 收尾时确认本轮是否新增债务；新增必须入账，编号顺延 |
| 不记"以后优化" | 无具体判据的愿望不入账 |
| 偿还即迁移 | 修好后从 §1 移到 §2，保留编号，不删除 |
| 债务有触发条件 | "偿还时点"必须可判定（如"首次出现实现类时"），不写"有空时" |
| 代码中的 TODO 必须带编号 | `// TODO(TD-02): ...`，无编号的 TODO 视为缺陷 |
