# DEV-003 测试策略

这份文档回答一个问题：**哪些逻辑必须测、测到什么程度、怎么证明测过了。**

## 1. 分层与门槛

| 层 | 范围 | 工具 | 门槛 |
|---|---|---|---|
| 单元 | 结存计算、红冲约束、状态机、指标口径 | JUnit 5 + AssertJ | 核心域行覆盖 **≥85%**，整体 **≥70%** |
| 集成 | 全部端点：正常 + 权限 + 校验失败 + 冲突 + 并发 | Spring Boot Test + Testcontainers（PG 18.3） | **端点覆盖 100%** |
| 架构 | 模块边界与分层依赖 | ArchUnit | 4 条规则全绿 |
| E2E | 三条主流程 | Playwright | **3 条全绿** |
| 手工 UAT | 12 条业务用例 | 人工 + 留证 | 全过 |

覆盖率由 JaCoCo 生成，低于门槛 CI 失败。**不追求行覆盖数字，追求断言有效**：一个只调用不校验的测试不计入覆盖统计（`@Disabled` 或空断言按缺陷处理）。

## 2. 必测清单

以下逻辑每一条必须有对应测试，缺一条即视为未完成：

| 编号 | 必测点 | 断言要点 |
|---|---|---|
| T-1 | 结存恒等式 | 任意流水组合后 `balance = Σ quantity`（含红冲） |
| T-2 | 红冲幂等边界 | 同一流水二次红冲返回 422，结存不变 |
| T-3 | 红冲符号 | 红冲流水 `quantity` 恒等于原流水相反数 |
| T-4 | 流水不可改删 | 直接 UPDATE/DELETE 被触发器拒绝 |
| T-5 | 物料/账号状态机 | 非法跃迁返回 422 |
| T-6 | 邀请码三态 | 不存在/已用/已禁用返回同一错误码，不泄露原因 |
| T-7 | 指标窗口 | 同一数据集同日两次请求结果完全相同 |
| T-8 | 跨单位禁止 | 统计响应中不存在未按单位分组的总量字段 |
| T-9 | 乐观锁 | 并发更新同一结存，后到者返回 409 |
| T-10 | 权限矩阵 | 11 个路由 × 3 角色，越权一律 403 |

## 3. 种子数据

- **禁止使用生产数据**，任何形式的导出、脱敏副本都不得进仓库。
- 种子数据固定且可重复生成：`src/test/resources/seed/` 下的 CSV 由同一个生成脚本产出，随机种子写死。
- 每个集成测试自行准备数据并在事务内回滚；不依赖测试执行顺序。
- Testcontainers 每次运行重建数据库，Flyway 从零迁移——这样迁移脚本本身也顺带被测。

## 4. 命名与组织

```java
class StockServiceTest {
    @Test void reverse_未红冲流水_结存回退到原值() { ... }
    @Test void reverse_已红冲流水_抛业务异常() { ... }
}
```

- 测试类与被测类同包（`src/test/java` 镜像 `src/main/java`）。
- 一个测试只验证一个行为；断言失败时的提示必须能直接读出"期望什么、实际什么"。
- 不写 `assertTrue(true)` 式的占位测试。

## 5. 不测什么

| 不测 | 理由 |
|---|---|
| 框架自身行为（Spring 事务传播、Jackson 序列化） | 上游已有测试；重复测只增加维护成本 |
| 私有方法 | 私有方法的行为应由其公开调用方体现 |
| 纯 getter/setter、DTO 映射 | 无逻辑分支，测了也只是覆盖数字 |
| 前端像素级视觉 | 用组件结构与交互断言替代，视觉回归不在 MVP 范围 |

## 6. 执行时机

| 时机 | 跑什么 |
|---|---|
| 本地保存前 | 对应模块的单元测试 |
| 提交前 | `make test`（单元 + 集成 + 架构） |
| CI | `make test` + 覆盖率门槛 + E2E（S3 起） |
| 发布前 | 手工 UAT 12 条 |

E2E 运行方式：先启动前端 dev server，再执行

```bash
E2E_ADMIN_PASSWORD=<当前管理员密码> pnpm --dir frontend e2e
```

开发环境管理员密码每次启动都会重生成（`DEV-001`），从后端启动日志读取；
`PLAYWRIGHT_OUTPUT_DIR` 可把失败产物指到临时目录，避免项目内批量删除触发安全策略。

## 7. 依赖漏洞扫描

| 项 | 内容 |
|---|---|
| 工具 | osv-scanner v2.7.0（Google OSV，联网查询 api.osv.dev） |
| 命令 | `osv-scanner scan source -r .`；Windows 下需 `HTTPS_PROXY` 走代理 |
| 范围 | Maven（`backend/pom.xml`）与 pnpm（`frontend/pnpm-lock.yaml`） |
| 门槛 | 无 High / Critical 已知漏洞 |
| 0.1.0 结果 | **0 High / 0 Critical**；5 条 Moderate（minimatch ×2、react-router ×2、vite ×1），均为开发期依赖或需要特定用法，记录在案 |

**0.1.0 的边界说明**：开发机**未完成** OWASP dependency-check 的完整 NVD 数据下载与扫描——
数据集体积大、本机网络受限，全量下载没有跑完。当前用 osv-scanner 的在线查询作为替代；
OWASP 全量扫描留给 CI 或带宽稳定的受控环境。两者覆盖范围不同，不能把 osv 结果当作 OWASP 的等价物。
