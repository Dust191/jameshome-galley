## 4. 文档规则

### 4.1 front-matter

十个字段缺一不可：`title`、`doc_id`、`status`、`owner`、`reviewers`、`created`、`updated`、`next_review`、`iter`、`related`。

`status` 取值与流转：`draft` → `in_review` → `approved`；被驳回时退回 `draft`。`accepted` 保留给「事项已定、文档待发布」的中间态，本项目实际只用前三个。

### 4.2 编号与前缀

任何新前缀须先在 `docs/00-glossary.md` §2.6 登记；`DEV` 只用于文档编号，`DVT` 只用于偏离条目，两者不得互借。
编号一经使用不回收，文档废弃时保留编号并在索引标注。

### 4.3 两种「状态」不得混用

`status`（front-matter）描述**文档本身**处在审定的哪一步；
正文首段的「状态」描述**所记事项**（决策、提案、问题）的裁定结果。
前者取值见 §4.1，后者由各文档自定，二者不得互相借用。

### 4.4 索引与关联

- 新增、改名、废弃文档都要在 `INDEX-001` 反映；
- `related` 只能指向存在的文档编号（`GOV-000`、`CONTRIBUTING` 等仓外文件已登记为外部标识）；
- `iter` 必须指向存在的迭代记录。

### 4.5 唯一门禁

`node scripts/check-docs.mjs` 是文档结构的唯一门禁，检查六项：front-matter 齐全、`status` 合法、`doc_id` 唯一、`related` 指得着、`iter` 存在、索引已登记；外加表格断行与**禁用写法零命中**。
CI 的 `guards` job 会跑同一条命令，本地不过就是 CI 不过。

### 4.6 迭代记录

每轮一份，命名 `ITER-YYYYMMDD-NN`。四要素齐全方可提交审定；**只增不改**——已经提交的轮次只能追加「补记」小节，不得回写原文，以免审计链断裂。审定栏三行（时间 / 结论 / 核对意见）由开发者填写或确认。

### 4.7 模板集

`docs/_templates/` 五份：`doc`、`dev`、`design`、`adr`、`ops`。新建对应类别文档时先复制模板，再删掉写作提示注释。

## 5. 代码、提交与依赖

| 面 | 规则 | 执行处 |
|---|---|---|
| 分支 | `main` 唯一长期分支；功能分支 ≤5 天；`hotfix/*` ≤24 小时 | `CONTRIBUTING` §2 |

| 格式 | 后端 Spotless，前端 Prettier + ESLint，不手工调格式 | `make lint` |
| 分层 | 模块间只经 `api` 包或领域事件；`domain` 不依赖框架 | ArchUnit 四条规则 |
