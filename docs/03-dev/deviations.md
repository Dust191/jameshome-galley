# DEV-007 偏离登记台账

这份文档回答一个问题：**哪些地方实现与规范不一致、为什么、影响多大、什么时候能收回。**

## 1. 记账规则

| 规则 | 说明 |
|---|---|
| 何时记 | 知道与规范不一致、暂时按现状走、且不一致有代价——三条同时成立才入账 |
| 不记什么 | 已经合规的、纯粹「以后想优化」的、以及规范本身允许的取舍 |
| 编号 | `DVT-NN`，顺延，不回收；与文档编号 `DEV` 严格区分 |
| 收回 | 收回后保留条目并标注日期，不删除——历史要能追溯 |
| 与规范的关系 | 台账记的是现实；现实与 `DEV-006` 冲突时以台账为准，并由台账反过来提出修订 |

**补记（2026-11-14，开发者裁定）**：

- `DVT-04` 的范围明确为三项同时不开启——`enforce_admins`、PR 批准数、以及 PR 的 `Prevent self-review` 检查；前两项的现状已记在条目里，第三项此前未写明。三者同在 S6 确认已有多人开发后一并收紧，在此之前开启只会挡住自己。
- `DVT-06` 的补做时间定为 **S5 阶段内**，不推迟到 S6；OWASP dependency-check 在带宽稳定的环境跑通全量后收回本条。
- `DVT-10` 的收回条件中「在 staging 用接近真实的负载证明」需修正理解：性能三项已改在 staging 实测，但 staging 是本地虚拟机，实测值只证明代码路径与查询计划在目标数据量下达标，**不构成 2C1.7G 可承载的证明**；本条继续生效。
